# 製造業のタイムカックを電子化し、月10時間の残業削減に繋げた話

製造業では「タイムカードの集計」が社員と管理者の双方にとって大きな負担になっています。
私は大阪の小さな木工所で生産管理を担い、**基幹システム入れ替えPJのリーダー**として現場のDXを推進してきました。
その中で「Docker + Python + Claude Code + Hermesエージェント」を組み合わせ、タイムカード電子化と**残業時間の見える化**を実現した事例を紹介します。

## 1. 課題：手作業の集計が招く「見えない残業」

従来の運用では、社員が紙のタイムカードに記入し、月末に事務方がExcelに入力するという流れでした。
課題は以下の通りです。

- **集計に月に10時間以上の工数**がかかっている
- **早朝・深夜の時間外手当の漏れ**が発生しやすい
- 生産管理システム（基幹システム）と勤怠データが分離しており、**コスト分析ができない**

特に、請負生産が多い木工所では「どの製品にどれだけの工数がかかったか」を正確に把握することが利益率の改善に直結します。
しかし、勤怠データがExcelで管理されていてはリアルタイムの分析は不可能です。

## 2. 施策：Docker Composeでシステムを構築

私は自宅のLinuxサーバー（x1lite）上にDocker Composeで環境を構築し、以下の構成で勤怠システムを自作しました。

- **バックエンド**: Python（FastAPI） × SQLite
- **フロントエンド**: 軽量な管理画面（内部利用のためシンプルなHTML/JS）
- **スケジューラー**: cronによる毎朝のレポート生成

全てをDocker Composeで一元管理しているため、バックアップや移植が容易です。

```yaml
# docker-compose.yml（抜粋）
services:
  api:
    build: ./api
    volumes:
      - ./data:/app/data
    environment:
      - DATABASE_URL=sqlite:///data/attendance.db
  cron:
    build: ./cron
    volumes:
      - ./reports:/app/reports
```

APIは打刻データを受け取り、SQLiteに蓄積します。
操作性を重視し、社員はスマホからも打刻できるようにしました。

## 3. Claude Codeによる業務ロジック実装

このシステムの肝は、**Claude Codeを使って開発速度を上げた点**にあります。
私は普段からClaude Codeを愛用しており、以下のように活用しました。

- 勤怠データから「時間外労働のアラート」を生成するロジックの実装
- 生産管理データと突合し、**製品別工数コスト**を自動集計する関数の作成
- Dockerfileの最適化と、CI/CDパイプラインの雛形生成

Claude Codeと対話的に開発を進めることで、従来の2倍近い速度でプロトタイプを完成させ、
現場のフィードバックを反映させながら改善を重ねることができました。

## 4. Hermesエージェントによる自動運用

システムが完成した後も、私は**Hermesエージェント**を導入し、運用を自動化しています。

- **毎朝8時に前日の勤怠データを集計し、 Slackに通知**
- 月次レポートを自動生成し、Googleドライブに保存
- 時間外労働が月45時間を超えた場合、自動で私にアラート送信

これにより、「毎日確認する」という管理者の負担を大幅に削減し、
**残業時間の事前防止**にもつながっています。

## 5. 結果：月10時間の削減とコスト可視化

導入から3ヶ月経過した時点で、以下の効果が表れました。

- 事務担当者の**月間集計工数が10時間削減**
- 時間外手当の**請求漏れがゼロ**になった
- 製品別の工数コストが可視化され、**原価率の高い製品の特定**が容易に

特に「原価率の高い製品」を特定できたことで、製造工程の見直しや外注先の見直しを実施。
結果的に**粗利を3％向上させる**ことができました。
