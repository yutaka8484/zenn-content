## はじめに：事務業務の非効率性と「1つの台帳」構想 見積書の作成から請求書の発行まで、紙ファイルとエクセルが散在する状況は、中小企業の事務業務ではよく見られる問題です。この非効率なプロセスでは、人手によるデータ転記が必然的に発生し、ミスの発生率が高まります。特に創業初期には事務能力が追い付かない状況が続き、請求漏れや入金確認ミスなどが頻発します。 これに対し、株式会社コバヤシでは創業前から「1つの台帳」をシステム化することを目指しました。世界で使われるOdooをベースに、見積・受注・請求・経費の全プロセスを一元管理するシステムを構築。同システムは、最初に入力されたデータが最後まで流れていく仕組みにより、転記作業を消去し、事務の正確性と効率を両立させます。 ## システム構成と技術選定：Odooを中心とするアーキテクチャ Odooはモジュール型のERPシステムであり、標準機能で見積（sale）・請求（account）・経費管理（expenses）がカバーされます。私たちは以下のアーキテクチャを採用しました。 ```plaintext 1. Odoo Core (SaaS版) → 基本機能提供 2. カスタマイズモジュール（Python） → 業務特化的ルール追加 3. データベース（PostgreSQL） → 1元管理台帳 4. ユーザーインターフェース → カスタマイズビュー 5. API連携（外部サービス） → 銀行連携・PDF自動送付 ``` 最大の設計判断は、SaaS版Odooを採用したことです。初期コストを抑える同时、セキュリティ更新やインフラ管理を外部に委託することで、少人数のチームでも安定運用を実現しました。カスタマイズは公式ドキュメントに基づくPythonエクステンションで行い、以下のポイントを実装しました。 - 見積書番号と受注番号の連動ルール - 請求書自動生成のトリガー条件 - 経費承認ワークフローへのCCメール機能追加 これにより、標準機能ではカバーできない製造業特有の要件（例：在庫管理との連動）を補うことができました。 ## ワークフローの設計：データの流れを可視化する実装例 見積→受注→請求の自動化ワークフローでは、以下のフローを設計しました。 ```plaintext 1. 見積書作成（sale.order） → ステータス：Draft 2. 客様承認取得 → ステータス：Sent → Confirmed 3. 受注変換（sale.order → account.move） → 請求書自動生成 4. 納品・入金確認 → ステータス：Invoice → Paid ``` この設計の判断根拠は、Odooの標準機能である「sales order to invoice」自動変換を活用しつつ、以下のカスタムフィールドを追加することでした。 - 納品予定日（Deliver Date） → 請求書発行条件  - 工数記録（Labor Hour） → 製作コスト計算連動  例えば、受注ステータスが「Confirmed」になった際に、自動で請求書スケジュールが登録され、納品日が過ぎた場合のみ請求書が発行される仕組みです。この設計により、「請求書を出し忘れた」というミスをシステムレベルで防いでいます。 また、経費管理では以下の実装を行っています。 ```python # 経費申請時の自動チェック（Pythonエクステンション）from odoo import models, fields, api class Expense(models.Model): _inherit = 'expense' @api.constrains('amount') def _check_expense_limit(self): for record in self: if record.amount > 50000 and not record.approved: raise UserError("5万円超過は管理者承認が必要") ``` これにより、5万円を超える経費は自動で承認ワークフローにルーティングされ、管理者が見逃すことがなくなりました。 ## 運用でハマったポイントと解決策 最初の1年では以下の課題が見 ヾいました。 1. **データ入力のユーザビリティ問題**：初期のUIでは、製造業特有の「工程コード」入力が非効率 2. **在庫管理との連携不足**：見積書作成時に在庫状況を反映できない 3. **請求書送付の遅延**：PDF自動送付機能がメールサーバーと連携しない これに対し、以下の改善を実施しました。 - **カスタムビューの作成**：OdooのQWebテンプレートで簡易入力画面を開発 - **在庫連動モジュールの導入**：stock.view_accessのカスタマイズで実現 - **SMTP設定の見直し**：送信メールサーバーを自社ドメイン認証方式に変更  特にSMTP設定では、Odooの設定ガイドに従いながら、以下の手順で解決しました。 1. 管理画面から「Settings → Email Settings」へアクセス 2. SMTPサーバーを自社メールサーバーに変更 3. DKIMレコードをDNSに追加してスパムフィルタ回避  これにより、請求書送付の成功率を99%以上に改善しました。 ## まとめ：正確な事務は「仕組み」で支える 株式会社コバヤシでは、Odooを中心とする業務システムを通じて、見積から請求までの二度打ちを完全に排除了しました。この設計判断の核心は、「人による転記作業を0にする」という原則です。実運用で得られた教訓は、標準機能の使い方とカスタマイズのバランスが重要であることです。 特に、初期のユーザビリティ課題は、継続的なフィードバックに基づくUI改善で解消。請求漏れ率は導入前比70%削減し、事務作業時間は月30時間程度の節約を達成しています。 詳細な設計ノートは、[株式会社コバヤシ デジタル実践一覧](https://kobayashi-works.co.jp/digital/)で公開しています。製造業のDXを検討中の皆様に役立つ情報を提供できることを目指します。
