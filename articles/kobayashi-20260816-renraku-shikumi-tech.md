## なぜ「連絡窓口」を最初にシステムとして設計したか

株式会社コバヤシは大阪・八尾の木工所です。創業にあたって最初に手を付けたのは、機械でも設備でもなく「連絡まわり」の設計でした。理由は明快で、事務専任者を置かない小さな会社にとって、電話・FAX・メールの取りこぼしはそのまま信用の損失に直結するからです。

一般向けにはこの背景を[会社サイトの記事](https://kobayashi-works.co.jp/digital/)でも紹介していますが、本稿ではその技術的な構成と、設計時にどこで判断を分けたかを詳しく書きます。

前提として、当社には電話番だけをする人がいません。私自身が工場で製作をしながら、同じ日に事務所の連絡にも対応します。つまり「人が注意して見落とさないようにする」という運用は最初から成立しません。だからこそ、注意力に依存しない仕組み、つまり構造そのものが取りこぼしを吸収する設計を先に組みました。対象は固定電話・FAX・メールの3系統で、それぞれ「誰でもどこでも受け取れること」を最優先の設計基準に置いています。

## 固定電話番号のモバイル化という設計判断

固定電話番号を出しておかないと、初めて取引する相手に不安を与えることがあります。一方で従来型の固定電話は、電話機のある事務所の机に紐づいてしまい、工場作業中は物理的に出られません。この「番号の信頼感」と「現場に出られる身軽さ」は、従来の電話インフラでは同時に満たせないトレードオフでした。

当社ではこれを、市外局番付きの固定電話番号をスマートフォンアプリで受け取れるサービス（03plus）で解決しています。発信者から見れば通常の固定電話番号ですが、着信は携帯電話網ではなくアプリ経由で私の端末に届きます。呼の流れを単純化すると次のようになります。

```
発信者 → 公衆電話網(PSTN) → キャリア側の番号ゲートウェイ
      → 専用アプリへプッシュ着信 → 手元のスマートフォン
```

工事や配線が一切不要という点も採用理由でした。事務所を借りたその日から番号を使い始められ、事務所の場所が変わっても番号を維持できます。トレードオフとして、着信はモバイル回線とアプリの可用性に依存しますが、固定電話機を置いて出られない状態を続けるリスクのほうが、小さな会社にとっては明らかに大きいと判断しました。

## FAXをメール受信に変える設計判断

建設・製造業では今もFAXでの発注や連絡が現役です。ただ従来のFAX機には構造的な弱点があります。事務所に戻らないと確認できない、紙が切れると受信できない、そして紙は物理的に失われます。

当社のFAXは、受信すると内容がメールで通知される仕組みにしています。狙いは単純で、FAXという入力チャネルを「紙の管理」から「データの管理」に変えることです。外出先でも受信の事実に気づけますし、内容はデータとして残るため「あのFAXはどこに行った」という探索コストが発生しません。

現状は届いたFAXの保存を手作業で行っています。これは意図的な判断です。受信頻度や送り主のパターンが十分に見えていない段階で自動振り分けのルールを先に固めても、実態に合わない設計になりがちだからです。まずは受信を確実に拾う仕組みだけを先に固定し、整理の自動化は運用データが溜まってから着手する方針にしました。今後実装するとすれば、件名や送信元番号をトリガーにした振り分けルールがイメージに近く、たとえば次のような形になるはずです。

```
# 今後の自動振り分けルール(実装イメージ)
if 送信元番号 in 取引先リスト:
    保存先 = "/取引先別フォルダ/{送信元}/"
elif 件名 に "見積" を含む:
    保存先 = "/見積書/"
else:
    保存先 = "/未分類/"
```

仕組みは一度作って終わりではなく、運用しながら育てるものだと捉えています。

## メールを役割別に分割するエイリアス設計

メールアドレスを1つに集約すると、注文連絡と広告メールが同じ受信箱に混在します。忙しい日ほど、その中に埋もれた1通の重要な連絡を見落とすリスクが上がります。ソフトウェア設計でいう単一責任の考え方を受信箱にもそのまま当てはめられると考え、当社では用途ごとにメールを分けて運用しています。

| 受信箱 | 受け取るもの |
|---|---|
| FAX用 | FAXの受信通知 |
| 業務システム用 | 見積書・請求書などの業務連絡 |
| ホームページ用 | サイトからのお問い合わせ |
| 営業用 | 新規のご相談・打ち合わせ |
| 経理用 | 支払い・入金に関する連絡 |

一般的なメール基盤では、こうした振り分けはエイリアス設定で実現できるはずです。イメージとしては次のような対応表になります。

```
fax@example.co.jp        -> fax-inbox
system@example.co.jp     -> system-inbox
info@example.co.jp       -> web-inbox
sales@example.co.jp      -> sales-inbox
accounting@example.co.jp -> accounting-inbox
```

それぞれの受信箱には「そこに来るはずのもの」しか届かないため、確認すべき連絡が他のノイズに埋もれません。複数の受信箱をまたいで確認する手間は増えますが、スマートフォンの1つの通知画面で全アカウントをまとめて見られるようにしておけば、実運用上のコストはほとんど気になりませんでした。

## 運用して分かったこと

3系統を仕組みとして固定した結果、電話・FAX・メールのいずれについても、担当者不在による取りこぼしという事態は今のところ起きていません。特に固定電話のモバイル化は、工場作業と事務対応を同一人物が兼ねる小さな会社の構造そのものに直接効いています。

一方で課題も見えています。FAXの保存自動化は依然として手作業のままで、受信件数が増えるほど負荷が上がる点は改善対象です。また、複数の受信箱に分けたことで「どのアドレスに何を届けるべきか」を取引先に周知するコストは発生しており、これは分割設計の副作用として認識しています。完璧な仕組みを最初から作るのではなく、確実に拾える最小構成を先に固め、そこから運用データを見て育てていく進め方が、専任者を置けない小さな会社には向いていると感じています。

株式会社コバヤシでは製造業の現場でこうしたシステムを自社実践しています。取り組み一覧: https://kobayashi-works.co.jp/digital/
