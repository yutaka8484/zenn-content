# 製造業のDXロードマップ：30日で“見えないコスト”を見える化する手順

製造業の経営者や工場長から「DXをやりたい」と相談を受けたとき、私は最初にこう答える：

> **「まず30日間、今の手作業を“数字に落とす”ことだけを目標にしてください。システム導入はその次です」**

実際に木工所の事業承継案件で、30日集中でやったことを整理した。小さな改善を積み重ねた結果、基幹システム刷新まで自然と進んだ。

## 1. そもそも“見えないコスト”とは

製造業で見えないコストは大きく3種類：

- **手間の見えないコスト**: 同じ作業を複数の担当者が別々にやっている
- **在庫の見えないコスト**: “型番”なのに材種・寸法が違うため集計不能
- **機会損失の見えないコスト**: どの案件にどれだけ時間がかかっているか不明

これらを **1ヶ月で“見える化”** するため、私は毎朝15分の観測を習慣にした。

## 2. 30日間の段階的アプローチ

### Week 1: 計測のみ（道具はExcelで良い）

| 日 | 観測項目 | 目的 |
|---|---|---|
| 1-3日 | 受注がどれだけ来ているか | 受注件数・金額の変動を掴む |
| 4-7日 | 1件の処理にかかる時間 | 担当者の負担を計測 |

**記録は1行で良い**：`2026-06-01,受注入力,Aさん,15分` のような形式で。

### Week 2-3: 計測を最小のDockerアプリ化

計測が2週間続くと「このデータ、システムで処理すると自動化できるかも」と担当者自身が気づき始める。  
そのタイミングで SQLite + FastAPI の最小アプリを作った。

```python
# 作業時間の登録
@app.post("/work-logs")
def create_work_log(entry: WorkLogIn):
    db.execute(
        "INSERT INTO work_logs (date, task, person, minutes) VALUES (?,?,?,?)",
        (entry.date, entry.task, entry.person, entry.minutes)
    )
    return {"status": "saved"}
```

すると：

- 前週比の所要時間推移が自動で出る
- 「どの作業が一番重いか」がグラフで見える
- 発注書→検品→出荷の各ステップの所要時間を追えるようになった

### Week 4: 見えた課題を1つに絞る

30日視点を終えると「材料の在庫が、実寸で何mm残っているか分からない」という問題が最優先に上がった。  
ここで初めて **基幹システムの刷新** に着手する。

## 3. システム刷新で避けた失敗

- **段階移行**：旧Excel（手続き）→ 新システム（Docker内のDB）を並行して3ヶ月運用
- **権限を絞る**：入力は1役割、閲覧は誰でもOK
- **現場と設計者を分けない**：担当者が作ったルールはコードに落とす時も原文を活かす

## 4. 結果：この30日間で生まれた変化

- **発注ミス**: 月3件→月0.5件
- **検品の所要時間**: 1時間→25分
- **在庫の存在しない材種の事故**: ほぼゼロ

「システム化した」と言うより、**「手順を見直したら副産物として残った」** と言う方が正しい。

## 5. 製造業がDXで最も大事なこと

- **現場のルールは変えない**：画面の設計に合わせて現場を変えるのはNG
- **数字から変える**：見える化が先、仕組み化が後
- **試せる土壌を作る**：Docker 内では何度でも壊して作り直せる
