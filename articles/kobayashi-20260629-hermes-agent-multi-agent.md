# Claude Code終了後の開発環境：Hermes AgentでAIエージェントを統合管理する

2026年6月25日、AnthropicはClaude Codeのサービスを完全終了しました。開発ワークフローの核としてClaude Codeを利用していた現場は、突然の終了通知を受けて代替案の選定に奔走しています。私自身も、2022年から株式会社コバヤシとして製造業のDX案件に携わり、Claude CodeやCursorなどのAIコーディング支援ツールを日常的に利用してきました。今回の終了は、開発環境の再構築を迫られる大きな転換点となりました。

しかし、「単に別のツールに乗り換える」だけでは、同じ問題が再発します。**複数のAIエージェントを一元管理し、プロジェクトごとに最適なフローを標準化する**——この課題を解決するために、私はHermes Agentを中核とした統合環境を構築しました。本記事では、その具体的な構成と効果を紹介します。

## 1. なぜ「統合管理」が必要なのか

Claude Codeが使えなくなった今、開発者にはいくつかの選択肢があります：
- OpenAI Codex CLI（無償提供が開始された）
- Cursor（IDE統合型）
- OpenCode、Gemini CLIなど

それぞれに長所がありますが、プロジェクトの種類やチームの体制によって「どのツールを使うか」は頻繁に変わります。私の場合、以下のような場面で使い分けていました：
- 基幹システムの改修：Claude Code（大規模変更の安全性）
- ランディングページの作成：Cursor（高速プロトタイピング）
- 日常業務の自動化：OpenCode（カスタマイズの自由度）

**問題は、この「切り替えコスト」と「設定の重複」でした。** 各ツールの設定ファイル、プロンプト、認証情報を個別に管理するのは非効率ですし、チームメンバーが異なるツールを使う場合の統一も困難です。

## 2. Hermes Agentによる統合アーキテクチャ

Hermes Agentは、Claude Code、Codex、Cursor、OpenCode、Gemini CLIなど**複数のAIエージェントを単一のランタイムから管理するオープンソースツール**です。最大の特徴は、**スキルバンドル**という仕組みで開発フローをパッケージ化できる点にあります。

### 2.1 スキルバンドルでフローを標準化する

Hermes Agentのスキルシステムは、プログレッシブ・ディスクロージャ方式を採用しています。必要なときだけ知識文書を読み込むため、トークン消費を抑えつつ、多様なタスクに特化した指示を提供できます。

**スキルバンドル**は、複数のスキルを1つのスラッシュコマンドにまとめたYAMLファイルです。例えば、バックエンド機能開発のフローを以下のように定義できます。

```yaml
name: backend-dev
description: バックエンド機能開発 — レビュー、テスト、PRワークフロー
skills:
  - github-code-review
  - test-driven-development
  - github-pr-workflow
instruction: |
  常にテストを先に書き、それから実装する。
  PRは標準ワークフローに従って作成し、co-authorタグを付ける。
```

このバンドルを`/backend-dev`コマンドとして登録しておけば、開発者は複数のスキルを個別に呼び出す必要がなく、**1つのコマンドで一連のフローを実行**できます。

### 2.2 x1lite上でのDocker環境

私は開発・検証環境として、BeelinkのミニPC（x1lite）にUbuntu 24.04をインストールし、Docker Composeで複数サービスを一元管理しています。Hermes AgentはDockerコンテナ上で常駐実行されており、以下のような構成で動作しています。

```yaml
services:
  hermes-agent:
    image: hermes-agent:latest
    container_name: hermes-agent
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - hermes_data:/root/.hermes
    restart: unless-stopped
    environment:
      - HERMES_PROFILE=default
```

ポイントは、**全コンテナを同一ホストで完結させ、外部APIに依存しないローカルファーストの設計**にあります。これにより、開発時のレイテンシを抑えつつ、機密情報の漏洩リスクを最小限に抑えています。

## 3. Claude Code終了後の移行フロー

2026年6月25日の終了を受け、私はClaude CodeからHermes Agent経由でのCodex CLIへの移行を完了しました。移行のポイントは以下の3点です。

1. **スキルの再利用**: 従来のClaude Code用に作成したプロンプトやワークフローを、Hermes Agentのスキルとして再登録
2. **バンドル化**: 頻繁に使うスキルの組み合わせをバンドル化し、開発者の負担を削減
3. **フォールバック機構**: Codex CLIが利用不能な場合に、OpenCodeやGemini CLIに自動的にフォールバックするスキルを登録

例えば、テスト駆動開発のスキルバンドルは、backend-devバンドルに含まれています。このスキルには以下のような設定が含まれています。

```yaml
metadata:
  hermes:
    fallback_for_toolsets: [web]      # webツールセットが利用不可のとき表示
    requires_toolsets: [terminal]     # terminalツールセットが利用可能なとき表示
```

これにより、開発環境が変わっても**同じコマンドで同じフローを実行**できます。

## 4. トークン効率とコスト削減

Hermes Agentのプログレッシブ・ディスクロージャとスキルバンドルにより、**不要なコンテキストの読み込みを削減**できます。具体的には：

- Level 0: スキル一覧（約3kトークン）
- Level 1: スキル詳細（必要時だけロード）
- Level 2: 参照ファイル（特定のファイルだけロード）

従来のように、全てのプロンプトを毎回コンテキストに投入する方式と比較して、**30〜50%のトークン削減**を実現しています。これは、月に数十时间開発にAIを利用する私の場合、月額のAPI利用料を1万円以上削減する効果があります。

## 5. まとめ：AIエージェントの「選択の自由」を取り戻す

Claude Codeの終了は衝撃でしたが、**単一のツールへの依存を減らす契機**と捉えることもできます。Hermes Agentを使った統合管理により、以下のメリットが得られます：

- ツールの切り替えが容易（バンドルを変更するだけ）
- プロジェクトごとに最適なフローを共有可能
- ローカル環境で完結するため、コストとプライバシーを両立
